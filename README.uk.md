## Встановлення

1. Завантажте архів із модулем
2. Розпакуйте папку `LogUserRequest-Lite` у `/lampac/mods/`
3. Відредагуйте init.conf. Дозвольте доступ до сторінки адмінки LogUserRequest-Lite: 
"accsdb": { 
"enable": true, 
"whitepattern": "^/lite/logrequest" 
},
4. Перезапустіть Lampac
5. Адмінка: http://ваш_сервер/lite/logrequest

## Налаштування модуля:
1. Конфігурація в manifest.json:

{ 
"enable": true, 
"version": 4, 
"namespace": "LogUserRequest", 
"logDay": 90
}
| Параметр | Опис | Значення за замовчуванням |
|---|---|---|
| enable | Увімкнути модуль | true |
| logDay | Скільки днів зберігати логі 90 |

Пароль адміністратора:
1. Змінна оточення (LOGUSER_ADMIN_PASSWORD=my-super-super-secret-key)
2. Пароль генерується автоматично при першому запуску та зберігається у файл: /lampac/database/LogUserRequest/passlogreg
(Подивитися пароль: docker exec lampac cat /lampac/database/LogUserRequest/passlogreg)

Що відбудеться при першому запуску

| Ситуація | Результат |
|---|---|
| ENV заданий | використовується ENV, файл не створюється |
| ENV порожній, файл немає | Створюється /lampac/database/LogUserRequest/passlogreg із випадковим паролем (36 символів) |
| ENV порожній, файл є | Використовується пароль із файлу |

⚠️ Важливо:
Якщо змінна оточення задана - має найвищий пріоритет, та інші джерела ігноруються.

Блокування при вході до LogUserRequest
Як працює блокування:

| Параметр | значення |
|---|---|
| Максимум спроб | 5 невірних паролів на день |
| Блокування | Після 5 невдалих спроб |
| Скидання лічильника | Опівночі (за UTC) |
| блокується | Тільки IP порушника (інші користувачі не страждають)

Що робити при блокуванні
1. Зачекати до півночі
Лічильник автоматично скидається о 00:00 UTC. (в коді `DateTime.Today.AddDays(1)` використовує локальний час сервера, переконайтеся, що часовий пояс UTC)
2. Змінити IP (якщо потрібно терміново)
Перепідключитись до VPN
Використовувати інший інтернет
Перезавантажити роутер

3. Перевірити правильність пароля
docker exec lampac cat /lampac/database/LogUserRequest/passlogreg

4. Скинути блокування вручну (потрібний root доступ)
Перезапустити контейнер (скине кеш спроб)
docker restart lampac

Скидання лічильника опівночі:
Зміни можна внести до Controllers/ApiController.cs
// У коді використовується
AbsoluteExpiration = DateTime.Today.AddDays(1)

## Інструкція з налаштування фільтрації в Lite-версії

### Де знаходяться фільтри

Усі фільтри знаходяться у файлі `LogUserRequestListener.cs` на початку класу `LogUserRequestListener`.

### Як працює фільтрація

Модуль використовує **три рівні фільтрації**:

1. **Автоматична (EventListener lampac)** - відсіває анонімні запити, локальні IP, службові ендпоінти ядра
2. **Список префіксів (`_skipPrefixes`)** — шляхи, що починаються із зазначених рядків
3. **Список розширень (`_skipExtensions`)** — статичні файли з розширення

Потрапляння до будь-якого фільтра — запит не логується.

---

### 1. Список префіксів, що пропускаються (`_skipPrefixes`)

private static readonly string[] _skipPrefixes =
{ 
"/.well-known", 
"/admin/health", 
"/admin/ping", 
"/testaccsdb", 
"/nws", 
"/lifeevents", 
"/proxyimg", 
"/lite/logrequest", 
"/lite/events", 
"/nexthub", 
"/externalids", 
"/lampa-main", 
"/lite/withsearch", 
"/timecode", 
"/bookmark", 
"/storage", 
"/cub", 
"/cub/", 
"/sisi/bookmarks", 
"/proxy/"
};

#### Як додати новий шлях:

private static readonly string[] _skipPrefixes =
{ 
// ... існуючі ... 
"/ваш_шлях", // Блокує /ваш_шлях і/ваш_шлях/що-завгодно 
"/api/internal", // Ще один приклад
};

### 2. Список розширень (_skipExtensions)

private static readonly string[] _skipExtensions =
{ 
".js", ".css", ".svg", ".png", ".jpg", ".jpeg", 
".woff", ".woff2", ".ogg", ".ico", ".map"
};

**Як додати нове розширення:**

private static readonly string[] _skipExtensions =
{ 
// ... існуючі ... 
".php", // Блокує всі .php файли 
".webp", // Блокує .webp зображення
};

### 3. Rate Limit (обмеження частоти запитів)

_rateLimitCache.Set(realIP, DateTime.UtcNow, new MemoryCacheEntryOptions
{ 
AbsoluteExpirationRelativeToNow = TimeSpan.FromMilliseconds(33), // ← інтервал 
Size = 1
});

**Як змінити інтервал:**

TimeSpan.FromMilliseconds(33) — ~30 запитів/сек з одного IP
TimeSpan.FromMilliseconds(100) — 10 запитів/сек
TimeSpan.FromSeconds(1) — 1 запит/сек

### 4. Максимальний розмір черги

private const int MaxQueueSize = 20000;

При перевищенні ліміту нові записи відкидаються з throttled-логом (не частіше ніж раз на хвилину).

#### 📋 Приклади фільтрації

| Що хочете заблокувати | Куди додати Код |
|---|---|---|
| Конкретний шлях /api/test _skipPrefixes | "/api/test" |
| Усі шляхи з префіксом /bot/ | _skipPrefixes | "/bot" |
| Усі .php файли | _skipExtensions | ".php" |
| Занадто часті запити | Rate Limit | Збільшити FromMilliseconds(33) до FromMilliseconds(100) |

#### Що фільтрується автоматично (EventListener lampac)

Це не потрібно додавати до списків - lampac робить це сам:
Статичні файли (js, css, png, svg, woff)
Анонімні запити
Локальні IP (127.0.0.1, ::1)
Службові ендпоінти lampac
Запити до авторизації

#### ⚠️ Важливі зауваження
Після зміни файлу потрібна перекомпіляція модуля
Синтаксис C# чутливий до регістру та ком.
Не видаляйте /lite/logrequest з _skipPrefixes — інакше сторінка модуля логуватиме саму себе
При помилці в синтаксисі модуль не завантажиться

## База даних
Шлях: /lampac/database/LogUserRequest/userlog.db

Очищення старих записів
У Lite-версії реалізовано **очищення днями** через параметр logDay manifest.json.
{ 
"logDay": 90
}

### Як працює:
Записи старші за logDay днів видаляються раз на добу
Перевірка запускається через 1 хвилину після старту модуля і кожні 24 години
Видалення відбувається батчами по 5000 записів для захисту від блокування SQLite при великих обсягах.
Після видалення старих записів також видаляються unfo і headers, що не використовуються.

**Код ModInit.cs:**

Код знаходиться в ModInit.cs, метод ClearJurnal. Вилучення відбувається батчами по 5000 записів.

**Чому батчами:**
SQLite блокує всю таблицю під час видалення
При великій кількості записів (100 000+) одиночний DELETE може зайняти секунди
Батчі по 5000 дозволяють іншим операціям (запис логів, читання адмінки) працювати між видаленнями

### Рекомендовані значення

| Сценарій | logDay: |
|---|---|
| Домашнє користування (1-5 користувачів) | 90 днів |
| Невеликий сервер (5-20 користувачів) | 60 днів |
| Великий сервер (20+ користувачів) | 30 днів |

Оптимізація SQLite (вже налаштовано)
У модулі застосовані:
WAL – прискорення запису
cache_size = -64000 - кеш 64 МБ
temp_store = MEMORY - тимчасові таблиці у пам'яті
mmap_size = 33554432 - memory-mapped I/O (32 МБ)

### Ручне очищення та редагування бази даних
Для редагування бази даних використовуйте **DB Browser for SQLite** - безкоштовний візуальний редактор.

🔗 Завантажити: [https://sqlitebrowser.org/](https://sqlitebrowser.org/)

Покрокова інструкція

1. **Скопіюйте** файл `userlog.db` з папки `lampac-docker/database/LogUserRequest/` у будь-яке зручне місце (це буде ваш бекап)

2. **Відредагуйте копію** у DB Browser for SQLite: 
- Відкрийте скопійований файл 
- Перейдіть на вкладку **"Execute SQL"** 
- Вставте та виконайте запити: 

DELETE FROM jurnal WHERE time < datetime('now', '-30 days'); 
VACUUM;

Збережіть зміни (Ctrl+S)

Замініть оригінал — скопіюйте відредагований файл у lampac-docker/database/LogUserRequest/ із заміною
Перезапустіть контейнер:

docker restart lampac

✅ Готово! База очищена, старі записи видалено.

📋 Альтернативні запити

| Завдання | SQL запит |
|---|---|
| Видалити більше 7 днів | DELETE FROM jurnal WHERE time < datetime('now', '-7 days'); |
| Видалити більше 90 днів | DELETE FROM jurnal WHERE time < datetime('now', '-90 days'); |
| Видалити ВСІ записи | DELETE FROM jurnal; |
| Подивитися кількість записів | SELECT COUNT(*) FROM jurnal; |

## 🕐 Час записів не збігається з місцевим
За замовчуванням модуль зберігає час запитів у **UTC**. Якщо в адмінці час відрізняється від вашого локального, це нормально, але можна налаштувати.

Варіанти розв'язання
1. Змінити часовий пояс контейнера (рекомендується)
Додайте змінну оточення TZ під час запуску контейнера:
docker run -e TZ=Europe/…
docker run -e TZ=Asia/…
Або в docker-compose.yml:
environment: 
- TZ=Europe/….
Після зміни – перезапустіть контейнер.
2. Якщо TZ не підтримується, потрібно змінити код модуля (⚠️Не рекомендується)
Якщо потрібно зберігати локальний час замість UTC, змініть у всіх файлах модуля
// Було
DateTime.UtcNow
DateTime.UtcNow.AddDays(-X)
DateTime.UtcNow.Date
// Стало
DateTime.Now
DateTime.Now.AddDays(-X)
DateTime.Now.Date

Не замінюйте:
DateTime.Now.Ticks
В іменах файлів експорту ($"export_{DateTime.Now:yyyyMMdd}.zip")

### ⚠️ Важливо: наслідки переходу на локальний час
| Проблема | Опис |
|---|---|
| **Перехід на літній/зимовий час** | Двічі на рік час зрушується на годину. Записи можуть дублюватись або порушиться сортування |
| **Зміна часового поясу сервера** | При переїзді на інший сервер усі історичні дані показуватимуть невірний час
| **Порівняння логів із різних серверів** | Якщо у вас кілька серверів у різних часових поясах – логи неможливо порівняти
| **Очищення за `logDay`** | Може видалити на годину більше або менше записів під час переходу часу |

#### 💡 Рекомендація: Залиште UTC. Браузер сам покаже локальний час. Це є стандарт для логування.

## ❓ Часті проблеми

### Модуль не завантажується
- Перевірте синтаксис в `manifest.json` (коми, лапки)
- Подивіться логі: `docker logs lampac | grep LogUserRequest`

### Не відкривається адмінка (404)
- Переконайтеся, що шлях `/lite/logrequest` не заблокований у чорному списку
- Перевірте, чи модуль включений: "enable": true`

### Пароль не підходить
- ENV змінна має пріоритет: `docker exec lampac env | grep LOGUSER`
- Перевірте файл: `docker exec lampac cat /lampac/database/LogUserRequest/passlogreg`

### База даних зростає занадто швидко
- Зменшіть `logDay` до 30
- Додайте в чорний список службові шляхи, що часто викликаються.

### Після входу в адмінку білий екран
- Перевірте помилку консоль браузера (F12)
- Переконайтеся, що файли `index.html` та `auth.html` не пошкоджені
- Очистіть кеш браузера

### Не працює кнопка "Premium"
- Це не баг 😄 - кнопка відкриває пасхалку та інформацію про Premium-версію
- Lite-версія повністю безкоштовна та функціональна
